# 主题图形与滚动预生成

新生成的在线区域必须提供 region.visuals，包含独立配色、地面材质、像素绘制配方、语义绑定和装饰分布。模型使用矩形、椭圆、多边形组成角色、建筑、机器、珊瑚等形状，Godot 将已验证数据编译为纹理。地图和战斗使用同一批纹理。

这条链路不需要图像模型，也不执行 LLM 输出的代码。尺寸、坐标、图形数量、颜色和引用均有校验；绘制数据与地图一起保存。主角沿用开场生成的形状和配色。旧存档与离线自检兼容原图集；要获得新的主题画面，请重新生成世界。

真实生成截图：

- [太空机械城](validation/space.png)：机器人、反应堆、管道、天线、霓虹金属地面。
- [海底珊瑚城](validation/coral.png)：鱼人、水母、珊瑚、贝壳结构与海水色地面。

两者的绘制几何由 DeepSeek 独立生成，不只是替换旧图集的颜色。当前仍是有限像素绘图原语，不代表专业美术资产质量或任意视觉风格都已实现。

## 预生成覆盖所有分支

默认在当前位置周围维护两跳范围：准备所有出口目的地，以及这些目的地的所有下一层区域。进入新区域后范围自动前移，返回旧区域也会补齐附近分支。不会沿整个无限世界递归展开。

已修复选择和开箱删除已准备地图，以及失败或延迟应用的世界反应阻塞其他预生成的逻辑。现有地图保持可进入，后台刷新不移除已建立的出口。单个分支失败也不阻挡其他分支准备。

同一模型最多两个请求在途，共享调用计数并去重，默认 low 思考不变。达到调用上限或网络失败时仍显示未完成状态；第一次生成图形和铺满缓冲需要时间。

## 验证记录

- 99 项 Python 测试通过，覆盖两层全部分支、无需移动即生成、进入后下一层已准备、刷新失败仍可进入、延迟反应不阻塞、两个线程不重复请求、图形校验及主角外观连续性。
- 原生图形检查验证矩形/椭圆/多边形真实像素输出，修改几何确实改变像素。
- 原生客户端 HTTP 流程、119 次操作和重新生成世界检查通过。
- 机械城落实了 7 个真实生成区域。移动步数为 0 时，两个直接出口和四个第二层区域全部 ready；逐个走入两个出口后，下一层均已就绪，往返未增加模型请求。
- 图形调试累计机械城 10 次 API 响应、珊瑚城 2 次。过程包含 JSON 修复、语义图形别名兼容修复，以及修复后对原始响应的重新编译，不将这些记录冒充一次全部通过的测试。
- 机械城累计输入 44,646、输出 110,603 tokens；珊瑚城输入 3,806、输出 16,617 tokens，输出包含思考。原始响应及 usage 在对应 userdata/visual-* 目录的 trace.json。并发请求耗时不能相加当作玩家等待时间。

独立启动验收存档，不覆盖正式存档：

```powershell
.\Start.ps1 -DataDir .\userdata\visual-space
```

正常 Start.cmd 继续使用 %LOCALAPPDATA%\EverweaveJRPG 中的正式存档。
