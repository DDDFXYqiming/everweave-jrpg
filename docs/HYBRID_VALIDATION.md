# 混合内容验收 · 2026-09-12

基于 `2d071cc`，开发分支 `codex/hybrid-content-library`。本轮是可运行的混合内容原型，不是完整内容库或画面品质保证。

## 本地验证

- 218 项 Python 回归全部通过，包含素材 ID/哈希/类型、越界组合、主角别名、模块碰撞、真实买卖/升降/战斗、声音事务回滚和存档重载。
- Godot 4.7.2 原生混合端到端通过。通过视口鼠标点击实际按钮，验证库图片、原创规则、机关开门、战斗数值、音乐切换和提交音效，无云端调用。
- Godot 音频专项实际读取音频采样，验证非零解码样本、原图像素一致性、叠加像素、交叉切换、循环、事件去重、短旋律与静音。
- 425 项素材文件哈希核对通过。通用入库工具在隔离目录验证了只读预览、实际入库及拒绝批内重复 ID。

## 真实在线生成与性能

使用既有 DeepSeek Flash、思考等级 low。同一小镇设定、独立空存档，纯生成与混合最终验收各请求一次，不启用后续预生成。生成内容非相同，因此只能作为一组观察样本，不是统计基准。

| 指标 | 纯生成对照 | 混合最终验收 |
|---|---:|---:|
| 成功应用 | 是 | 是 |
| 模型请求 / 修复请求 | 1 / 0 | 1 / 0 |
| 模型请求耗时 | 147.704 秒 | 102.656 秒 |
| 输入 tokens | 3,492 | 5,845 |
| 输出 tokens（包含思考） | 37,057 | 23,690 |
| 其中思考 tokens | 26,348 | 18,153 |
| 输入＋输出 | 40,549 | 29,535 |

最终混合样本“雾河邮镇”生成并应用约 103 秒；请求耗时下降约 30%，输出 tokens 下降约 36%，输入加输出下降约 27%。候选信息使输入增加，输出及思考仍占主要开销。该样本使用 16 个库图配方、7 个原创配方、2 个可选玩法模块；不把数量比当作画面面积或质量比。

调试过程也有成本：含纯生成对照共 13 次真实请求，累计输入＋输出 366,483 tokens。早期曾因音效别名、短动画、字段位置、缺少主角、无效 JSON、对象不可达而失败。所有原始响应、失败记录和调用数据保留在本机 `userdata/hybrid-validation`；这些开销没有摊入上表的“最终验收”。

地下样本经历两次初始/修复请求和一次带精确空间错误的修复。模型实际修正了不可接近的轮盘与箱子；随后本地补齐“短乐句 cue 作为特殊音乐”的解析支持，原始响应零新增请求重放成功。它不能被描述为首次在线生成成功。

随后目视发现树冠碎片被错误推荐为完整树木。已停止推荐这些旧 ID，新增冠/干正确拼接的两个 v2 树木 ID，旧文件与旧存档继续保留。地表候选补充基底/点缀用途。修正后的另一次在线生成也成功，但因初始装备不匹配触发一次模型修复，总耗时 136.886 秒，输入 22,028、输出 36,814 tokens。其总 tokens 比纯生成对照高约 45%，说明修复开销足以抵消节省，不能只选取上表的一次成功就宣称稳定降本。该世界作为本轮最终打开的试玩存档。

## Windows 自主试玩

使用 Computer Use 观察实际画面、自主选路和点击；没有改坐标代替移动，也没有写通关脚本。

- **苔桥镇**：移动到铜灯旁，E 打开操作，点击“看铜灯眨眼”；出现桥头绞盘生锈的线索。日志确认执行 `lamp_listen`，故事版本增加，原图与原创叠加共同显示。
- **回声档案馆**：从入口走到升降台绞盘，点击下降，到下层操作制动轮盘，再点击上升返回。日志确认两个模块操作分别更新到合法落点；UI、碰撞、动作与存档一致。
- 原用户存档和原用户游戏进程未改动。试玩采用独立数据库，导演暂停，无额外后台生成消耗；继续生成由游戏内“继续生成”恢复。

## 已知边界

房屋、角色、道具的形状辨识度提高，前端能同时呈现库素材、组合与原创图像。但部分场景仍稀疏；地下样本把高对比石块铺满大厅，视觉重复明显。已给候选补充基底/点缀用途，后续应继续扩充一致风格和更安静的地表，而不是用硬编码改写已经生成的场景。

第一批主要覆盖小镇和地下主题，4 首背景音乐和 4 个玩法模块，不是海量全题材库。没有验证长时间游玩、多世界统计成功率、任意复杂音频配器或独立导出发行包。索引、参数和导入工具已留出正常扩库入口。
