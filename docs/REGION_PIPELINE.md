# 地区双路制作管线

在线章节中的复杂新地区不再由一次模型请求同时编写地图、规则、像素画和音频。全局导演已经保存了地区名称、用途、持续人物、题材和路线职责；`region_pipeline.py` 从这些权威数据在本机形成一份小型约定，不再额外调用模型复述它们。

```text
章节与冒险导演的现有委托
          ↓ 本机形成地区约定
   ┌──────┴────────┐
   │               │
玩法制作           视听制作
地图与碰撞         素材检索与组合
对象与交互         角色/物件/地表图形
对白、战斗、任务   音乐与音效
   │               │
   └──────┬────────┘
          ↓
  本机交叉检查并合成完整 region
          ↓
  原有 Schema、玩法和世界事务校验
```

两条请求都固定使用 GPT-5.6 Luna / high，并通过同一个 ChatGPT 订阅直连同时执行。玩法分支不接收素材大目录，也不输出 `visuals/audio`；视听分支不接收程序、坐标和未来剧情。共同约定固定地区名称、持续人物身份、允许的语义图形槽和四种地表槽。玩法可以创作本地区临时对象，但只能引用约定中的视觉槽；视听可以自由选择、组合或绘制素材，但不能改变人物、地图和规则。

组装前会检查持续人物、视觉引用和地表实际使用，视听数据先做组件校验。视听或玩法组件单独失败时，在尚有额度的情况下只把该组件及其错误交回模型修一次，另一条成功结果保留。组装后仍走原来的完整 `parse_patch`、地图可达性、规则引用、奖励和事务校验。组件预检不会把材质提前展开，避免主校验再次解释同一份材质。只在含章节/冒险委托的复杂新地区启用；旧式单地区、刷新、修复、离线模式、其他 provider，以及剩余请求额度不足两次时仍走一次生成。

每个真实请求分别计入额度。一个首次成功的双路地区显示为一个生成任务、两次模型请求；单组件修复会再计一次。同一时间只运行一个双路地区，避免原有两条调度线程各自再展开两路。任一传输失败不会自动重放。完整地区校验仍失败时会保留已组装结果和诊断，按原来的定向修复流程处理。

## 2026-09-16 实测

同一个“黑檐夜市”未生成首区存档此前用单一 Luna / high 直连请求耗时约 **296 秒**。三请求原型先用模型生成约定，再并行制作，约定本身需要 43～74 秒，总耗时 290～333 秒，因此被舍弃。

最终双路版本由本机从导演数据建立约定。玩法和视听同时开始，玩法约 **136 秒**开始输出、**197.7 秒**完成整个任务；两次请求合计输入 **8978**、输出 **19433** tokens。墙钟时间相对 296 秒样本降低约 **33%**，但输出 token 总量增加，因为两条 High 请求各自包含推理。这个单样本只能证明管线确实并行且有可观的等待时间改善，不能保证每个地区固定提速三分之一。

这次模型结果暴露两类可确定纠正的协议偏差：视听字段被缩进 `music`，以及布尔对象状态只写了 `true` 却漏掉初始 `false`。前者在没有同名冲突时归位；后者仅对“区域初始定义中，缺失字段确实被布尔 `set true` 使用”的情况补 `false`，并写入本地纠正记录。非布尔或不明确的初值仍失败，不猜玩法。

修正后把这两次请求的原始组件重新经过完整组装、Schema、世界可玩性和事务应用，生成 32×20 的“黑檐夜市”，包含谈判分支、持续人物、消耗弹药的调查、守卫敌人、任务推进和隐藏路线。快速试玩以 9 次正常移动靠近秋叶，选择高风险报酬后真实资源从 0 变为 120，主任务完成并揭示第二条路线。Godot 4.7.2 通过真实客户端和本机 HTTP 加载该存档，编译 17 个生成图形并启用地区音乐，模型调用为 0。

原始计时、组件回答、日志和回放后的测试数据库保存在本机 `userdata/region-pipeline-two-way-20260916/`，不提交 Git。复测使用 ChatGPT 订阅，没有调用 DeepSeek，也没有降低 high。
