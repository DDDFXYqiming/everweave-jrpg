# 生成协议与 Windows 验收（2026-09-12）

本轮在 Content Runtime v2 的基础上改善模型输出适配与失败诊断。没有删除出错的玩法规则、伪造缺失物品或用离线样例替换在线内容。

## 处理顺序

模型 JSON → 无歧义格式纠正 → 按作用域解析定义与引用 → 收集独立错误 → 校验地图与可执行规则 → 原子应用。

- `normalization.py` 集中处理单一明确外壳中的字段层级、`sprite_id` / `itemId` 别名、单句对白数组，以及可安全纠正的新定义前缀。每次纠正记录原位置、原值和结果。
- 定义按物品、对象、精灵、变量、操作、钩子、目标等作用域分别建表。新 ID 的重命名会同步到锚点、绘图绑定、规则表达式和效果中的相关引用。普通对白、描述及事实文本不做全局替换。
- 已有跨地区物品的规范 ID 保持不变，包括新地区的宝箱与收集目标。冲突、同名歧义和将既有身份重新声明为新定义的情况仍然拒绝。
- 世界变化中新建的物品保存 `local_id` 与 `origin`，规则可以引用同一份补丁刚注册的物品。旧存档使用引擎已知的事件 ID 格式恢复本地别名；多义匹配不会任选一个。
- 未定义物品、对象和精灵可与独立的字段错误一起回报。诊断包含字段路径、分类、原值和期望，单次最多列出 20 项；不会每次只告诉模型一个模糊的 `id` 错误。
- 地图变化、对象注册和新规则会在隔离的内存存档中完整验证，再对真实世界原子提交。玩家位置、出口、引用一致性和执行预算检查继续生效。

纠正记录随地图保存，最多保留最近 128 条。描述性 `visuals.style` 允许 450 字符，避免 83 字符的风格说明使整个可玩地区作废；JSON 总体大小、图形几何与执行预算仍然有界。

## 失败与重试

界面分开显示请求、其中的修复请求、在途任务、已应用内容、过期结果、失败任务和本地纠正数量。每个失败任务标出地区、生成类型和问题类别，显示首个错误位置，完整诊断保留在提示中。

每个任务有独立重试按钮，也可重试当前所有失败项。成功地图不会被重新请求。手动重试仅在世界版本仍匹配时复用之前失败的 JSON；正常生成的自动修复机会仍然最多一次。过期的错误响应不会变成新世界的失败任务，也不会再消耗一次无意义修复。

## 验证

- Python 3.13.6：167 项自动测试全部通过，覆盖原有运行时、新 ID 映射、跨地区身份、碰撞拒绝、多错误报告、定向重试和过期任务。
- Godot 4.7.2：客户端、像素与动画像素、可执行内容检查通过。
- 原有客户端 HTTP 端到端测试通过 119 次操作和世界重建检查。
- 新增原生 HTTP 验收覆盖失败任务的独立重试、逻辑键码与短按移动、自定义操作、开门、复合目标和自定义战斗；同时在无头与 Windows OpenGL 原生渲染模式执行。
- 原生输入测试使用 [Viewport.push_input](https://docs.godotengine.org/en/stable/classes/class_viewport.html#class-viewport-method-push-input) 将事件送入实际视口与 UI 分发链，不依赖测试窗口获得系统焦点。

真实 DeepSeek 使用 `low`，从正在游玩的存档建立隔离副本，测试“歌舞伎町夜市”的生成。调试中实际暴露过风格说明长度、缺失精灵与未定义物品问题；修复后的原响应通过真实模型的定向修复，已生成可进入的下一地区。没有手工补写模型物品或规则来冒充在线成功。

本次真实联调共 6 次请求，包含调试失败及修复，不作为一次生成成功率。最后两次定向修复分别约 37.45 秒、34.84 秒，均让下一地区通过完整验证。对真实失败响应的离线回放同时报告了 11 处格式与引用问题；最终响应补齐所需物品，保留原有操作、钩子和目标 ID，无新增云调用。

本地证据位于 `userdata/protocol-validation-20260912/`，包含原始响应、usage、错误与结果；原生界面截图位于 `userdata/content-e2e/`。这些文件和个人存档不随 Git 上传。

这是有限样本的联调结果，不保证任意模型内容一次成功或任意谜题可解。缺失定义、冲突身份和非法玩法仍需真实修复；界面会明确指出它们，不会静默丢弃规则。

```text
python tools/test_protocol_live.py --live --from-save <现有 world.sqlite3> --output <新的隔离目录> --max-calls 4
```
