# 旅途地图与世界专属开场物品

> 阶段说明：此文保留旅图和物品功能建立时的记录。章节世界的实际道路来自 campaign links，不能只用 topology 的 parent/children 还原；锁闭路线与隐藏路线规则见 [CAMPAIGNS.md](CAMPAIGNS.md)。

2026-09-12。接续前端版本 `8b01093`，此版本实现旅图、开场物品、物品使用状态、长期手记与独立重创入口。

## 旅途地图

点击区域右上角小地图，或按 G，打开旅行手册式的连接图。支持拖动、缩放、名称搜索、定位当前位置、地点说明、待办书签、分支收起与路线标记。旧地点的布局位置保持稳定，视野、折叠状态与目标标记按世界保存在本机。

地图只读 `World.state.topology` 中的实际连接。已到访地区显示名称、描述和从实际地形采样的缩略图；已发现但未进入的出口只显示已知目的地名称及状态。纯后台预生成的第二层地区、未访问地区的角色/谜题/物品/缩略图均不披露。模型描述中提到的地名不自动变成地图道路。

`GET /atlas` 在打开地图或已知连接变化时按需读取，带原有本机令牌鉴权。返回轻量节点和边；不发送完整地图、规则或绘图配方，不调用模型，也不把旅图数据添加到模型上下文。它不使用模型提示词中截断的 `known_locations`。

路线通过已知连接做 BFS，仅显示出口名称与地区数量，不传送，不跳过房间内的机关。节点达到较多数量时可折叠后方支路；搜索或标记路线会展开相关支路。渲染会略过视野外的地点卡片。

## 开场随身物品

新的在线世界通过开场 `region.starting_loadout` 定义随身物品：

```json
{"inventory":[{"item_id":"repair_gel","count":2},{"item_id":"wrench","count":1}],"weapon":"wrench"}
```

所有引用必须在同一开场的 `region.items` 声明；要装备的物品也必须列入 inventory。最多 8 种、合计 20 件；装备类型必须匹配。验证、物品注册、图标冻结和一次性发放在同一个事务内完成。失败响应不会部分发放，重复/迟到的开场响应不会再次发放。后续地区与反应不能使用这个开场字段。

开场生成前背包为空；在线世界不再注册固定全局三件套。旧存档与显式离线样例沿用原有物品，不删除既有财产。内部 `World.start(..., authored=False)` 保留离线/旧测试兼容，真实在线 `/start` 明确传入 `authored=True`。

新在线世界的商人不自动补进固定药剂；有敌人的新地区必须带模型定义的战斗操作。旧战斗保留兼容，同时装备为空时可以正常处理。`potion` 等字符串在新世界可以是一个普通的地区内 ID，但不会自动映射为原来的固定物品。宝箱必须明确声明物品引用。

此版本仍保留基本数值系统、物品类别和受控效果。它没有声称整套成长或战斗基础规则都已变成模型任意程序。

## 使用条件、记录与重试

物品快照附 `usable.enabled / blocked_reason / label`，由后端用当前状态判断。自定义条件在私有视图中求值，不执行效果；真正使用时仍重新验证。前端显示结果，不另建规则解释器。

`GET /journal` 按分类和游标翻页，默认 30、最多 50 条。任务与线索读取完整存储；新经历写入独立 SQLite journal 表，和游戏动作一起提交/回滚。常规 `/state` 仍只带近期记录，模型上下文也未扩大。

旧存档会导入仍保留的经历；旧版本已经丢弃的文字不能完整恢复。完整的持续保存从本版开始。

失败任务的普通重试仍保留原 JSON 和具体错误。另有“放弃候选，重新创作”，经明确的界面确认后，只清除该失败地区的候选缓存，保持目的地、已准备地图及其他任务；请求仍计入原预算。它不等于重建当前世界。
