# 后台预生成与耗时验收（2026-09-12）

> 阶段说明：此文记录章节系统之前的地区/反应调度。章节世界新增 campaign 任务，并禁止用 reaction.locations/future_updates 改写章节连接。当前调度见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 原因与处理

预生成原本就会由两个后台线程启动，并覆盖全部出口及下一层。主要缺陷是地区请求与当前地图共享 `story_revision`：玩家交互、开箱或战斗推进故事时，尚在生成的另一地区被丢弃。受控并发复现中，两次请求均成为过期结果，两个出口都未准备好。

地区请求现在使用世界 epoch、目标地区的大纲版本及父地区身份判断有效性。普通故事事件不会取消它，也不会把所有已准备地区标成需要重画。世界变化仍校验当前地区与故事版本，避免把旧反应应用到新的行动结果。

模型可用 `reaction.future_updates` 明确改变尚未访问的直接出口大纲；只让对应地区重新生成，旧草案在更新期间仍可进入。进入后冻结该草案，迟到更新不能覆盖已访问内容。旧存档自动清理旧策略留下的无明确原因刷新标记，无需重建世界。

## 协议与空间校验

- 新地区请求只发送故事、身份、目的地与相关语义摘要，保留完整内部校验上下文。当前存档相同上下文的 UTF-8 JSON 从 31,351 字节减至 11,477 字节，减少 63.4%；这不是延迟下降比例。
- 明确区分地形碰撞类型和金属、木材等视觉材质。错误会一次指出 `region.scene.base` 与具体 `paint[n].tile`，而非让模型逐次猜字段。
- 物体可达性与真实交互保持一致，检查整个占地边缘。真正被不可通行地形隔离的对象仍会被拒绝，不自动挖路或删除规则。结构检查并不证明任意谜题可解。
- 世界变化请求明确只处理当前事件的局部后果，避免重做整张地图或已有规则。保持 `low`，v2 反应输出上限为 32K（含思考），上限不是要求生成的长度。
- 达到调用预算时保留原始校验诊断，不用“调用上限”覆盖可修复的具体错误。

DeepSeek 的 JSON 模式保证 JSON 格式，不保证满足本项目的全部空间与玩法契约；截断由 `finish_reason=length` 标识。见[官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

## 界面与日志对齐

出口等待窗口绑定实际目标地区状态。后台完成后窗口直接变为可进入，按 E 进入，无需关闭再触发。失败时可定向重试；返回当前地图继续探索不会停止后台生成。服务端仍检查出口邻接，不能通过按钮远程传送。

右侧逐任务显示自动预生成、草案更新或世界变化、耗时与修复阶段。`task_history` 保留最近 24 个任务的开始步数、故事版本、请求耗时、校验耗时与结果；接入日志任务的 JSONL 记录 `generation.started` / `generation.finished`，同一次运行可与模型请求、错误及真实玩家操作对齐。详见 [LOGGING.md](LOGGING.md)。

界面同步调整。暂停/重试按钮固定在右栏顶部，不随失败列表滚动；F 空菜单解释附近没有自定义操作；禁用按钮直接显示模型的 `blocked_hint`，或公开的物品/金币/魔力不足信息。任意隐藏变量不会被翻译成谜底；旧内容无明确线索时给出中性说明。

实际运行日志中，一次成功地图任务总耗时 171.11 秒，请求耗时 170.841 秒、校验 0.068 秒。另两次失败任务分别请求 188.416 / 218.199 秒、校验 0.118 / 0.129 秒。主要时间消耗在模型生成与修复；不能把失败原因等同于校验计算慢。

## 验收证据

- 185 项 Python 测试通过，包含日志任务的 3 项测试。
- 真实双线程、玩家零移动：两层共 6 个地区准备成功，无出口操作。
- 两次预生成进行中执行真实引擎交互：两份均应用，过期 0。
- Godot 4.7.2 原有 HTTP 验收 119 次操作通过。
- 原生可执行内容验收在无头与 Windows OpenGL 模式通过，新增等待窗口实时就绪和 E 键进入验证；原有自定义动作、机关、目标、战斗与重试覆盖保留。

该阶段在隔离存档中进行了 5 次真实 DeepSeek 请求。早期反应仍在 16K 截断；一份新地区生成耗时 167.50 秒，因把 `metal` / `wood` 当碰撞类型而失败。对原响应两次定向修复耗时 22.16 / 34.16 秒后，落雨天台通过完整验证并成为可进入地区。最终收紧范围的世界变化请求耗时 6.86 秒，925 输出 tokens（含 562 思考），一次验证并应用成功。

第一次地区修复已纠正地形，却回显了协议元数据 `type:json_object`。现在只在完整且类型明确的外壳中移除这项无玩法含义的元数据，并记录纠正；原响应离线回放即可通过，避免为这项格式偏差再请求完整内容。其他未知字段不会静默删除。

这些是有限样本，不是全局成功率或稳定平均延迟。新地区完整生成依然可能花数分钟。调试原始响应、结果及截图位于本地 `userdata/prefetch-validation-20260912/` 与 `userdata/content-e2e/`，不随 Git 上传。
