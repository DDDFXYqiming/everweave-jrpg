# 运行时约定

## 谁能决定什么

项目目标是由 LLM 持续驱动的 Godot AI-JRPG Runtime。世界设定是玩家的输入；具体地点、角色、物品、任务和后续内容由模型在运行时创作。固定离线样例只用于引擎测试。普通功能验证通过，不能替代真实生成链路的验收。

LLM 拥有内容创作权，不拥有已经发生的结果的写权限。它能从固定字典组合一张新地区的语义蓝图、NPC、敌人、道具、任务和叙事。引擎保留位置、库存、生命、伤害、金钱、角色战败、地图连接和存档的最终决定权。

LLM 没有文件路径、网络访问、执行脚本或加载任意资源的指令。显示文本按普通文本处理，不按 HTML 或 BBCode 执行。

## 两种输出

`kind=region` 产生尚未进入地区的蓝图。`kind=reaction` 对既有地区产生有限补丁。完整字段与枚举以 `engine/schema.py` 和 `engine/director.py` 为准，示例见 `example-region.json`。

区域生成包括：

```text
地区名 / 描述 / biome / layout / weather / rule
地标的类型和语义方位
NPC 或敌人等实体及它们的语义方位
新物品的效果组合和预算
必须能解析到实际对象的任务引用
可延续的 lore 与故事线
destinations：模型声明 1～2 个后续地点的 id、名称与概要
```

反应补丁包括：

```text
说明发生了什么
更改天气或一种已实现的区域法则
更新现存 NPC 的对话
最多增加两个受限实体
最多增加两个新物品、两个任务、两个地点入口
增加 lore 与未来故事线
```

反应不能替换已访问地图，也不能把“你获得了某物”当成库存修改。新物品通过地图上真实的箱子和商店获得；战斗胜利必须通过代码结算。

## 地图与预取

每张地图 52×36 格。模型输出风格、布局和对象意图，`pcg.py` 用种子构造地形，铺连接道路和桥，摆放实体并检查可达性。有限的地形图块是原子素材，不是几张完整地图的轮换。

在线新地图的前向道路由模型声明，运行时生成稳定 ID 和可通行入口。选择、开箱或胜利将未访问草案标为待刷新，保留原可用版本；刷新必须保持现有出口 ID，玩家先行进入时丢弃旧刷新响应。目的地概要、原始设定、最近事件、物品和父区域草案均进入生成上下文。

已访问区域不重建地形。回访从 SQLite 读取之前的实体状态和地图；宝箱、敌人、任务领奖均保留。新地区的物品、任务和 lore 在首次抵达时才成为正式世界内容，避免预取内容提前污染已知世界。

## 单模型调度与一致性

同一个模型最多两路请求并发，共用预算与任务去重。优先级是初始地区、缺失的直接出口、世界反应、第二层缺失地区、已备好草案的刷新。使用当前位置周围的两跳范围，进入新地区后自动前移。普通移动和战斗回合只运行本地逻辑。

模型调用不持有世界锁。响应完成后必须再次通过 schema 校验、世界 epoch 校验和 story_revision 校验。旧世界、旧配置或不再适用的回应被丢弃。战斗或对话进行时的反应暂存到交互结束，避免在回合中途偷偷改变规则。待反应标记保存在存档中，退出后仍能继续处理。

每次网络请求计数；JSON 验证失败最多修复一次，且修复也受调用总量限制。网络失败、模型不存在、超时、返回截断等不会无限重试。坏内容不执行，也不无声伪装成“AI 成功”。离线演示必须显式选择。

新物品和实体先注册到同一补丁的命名空间，任务引用随后解析。悬空物品或任务引用会进入有限修复流程。应用失败时整份补丁回滚，不留下孤立物品或半条道路；玩家库存只在实际取得物品时变化。失败的世界反应保留待办状态，手动重试会重新处理。

## 存储

SQLite 表：`state`（元数据、玩家、任务、事实）、`regions`（每张已生成地图）、`events`（时间顺序事件）。涉及状态和地图更新的存储采用 SQLite 事务。运行时区域 LRU 缓存最多六张；历史地图留在磁盘。元数据仍随旅程增长，当前实现不声称已经验证上万小时世界。

只有一个存档槽，创建新世界需明确确认覆盖。启动器以独占锁文件阻止两个实例同时使用同一存档目录。崩溃后锁文件可能残留；确认没有游戏/启动器进程后才可移除 `instance.lock`。不要删除仍运行实例的锁。

## 客户端

Godot 通过两个独立 HTTPRequest 分别进行轮询和提交动作。动作串行发送，不自动重发；每个请求携带唯一 ID。服务器会去重，防止响应重试引发重复购买。客户端对旧版本快照和已淘汰世界 epoch 进行过滤。

渲染层只读取已验证的图片枚举和地图数据，使用原生 Godot CanvasItem 绘制像素图块、精灵、跟随镜头和天气。LLM 不直接访问场景树或执行 GDScript。

## 当前刻意保留的限制

树状地图而非任意环状世界；一个玩家角色而非小队；固定战斗/任务原语；建筑没有室内；剧情选择来自生成的选项，不是无边界自由文字行动；未实现实时生成新角色画稿。该实现验证的是“游玩时模型持续改变可玩的世界”这一闭环，而不是用有限代码声称完成无限制 JRPG 引擎。
