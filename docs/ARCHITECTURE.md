# 运行时约定（Content v2）

当前主协议见 [EXECUTABLE_CONTENT.md](EXECUTABLE_CONTENT.md)。格式适配、身份解析与失败诊断见 [PROTOCOL_RELIABILITY.md](PROTOCOL_RELIABILITY.md)。旅图知识视图、开场物品和手记分页见 [JOURNEY_AND_POSSESSIONS.md](JOURNEY_AND_POSSESSIONS.md)。最初 v2 源码包的验证保留在 [REFRACTOR_TEST_REPORT.md](REFRACTOR_TEST_REPORT.md)。

## 数据链

玩家世界设定 → 单模型导演 → `region.scene + program + visuals` → 校验与施工 → Godot 渲染与输入 → 本机规则解释器 → 真实事件 → 导演继续创作。

`engine/schema.py` 保留旧存档语法并接入 `content.py` 的空间与程序语法。`scene.py` 执行模型指定的几何、房间和锚点；只有旧数据继续通过 `pcg.py` 的随机铺图。`runtime.py` 是无宿主脚本权限的有界解释器；`gameplay.py` 将其连接到已有玩家操作、战斗和原子存储。

在严格校验之前，`normalization.py` 维护定义与引用的分作用域映射，纠正有唯一解释的格式差异；`diagnostics.py` 提供带路径、分类、原值和期望的多错误报告。既有身份与自然语言文本不做全局改名。`Director.failed_tasks` 与在途、过期和成功结果分别计数，重试按任务选择。

程序数据使用显式变量、表达式、条件、效果和事件，而非只让模型选择有限任务枚举。模型仍不能随意覆写 player 字典或历史事实；受控效果只能在玩家操作及相应规则执行时改变状态。

## 两种输出

`kind=region` 创作尚未进入区域。模型声明尺寸、地形绘制、出口锚点、实体、图形、交互程序和目的地。预取内容不会提前授予物品；首次进入才注册其物品和目标。

`kind=reaction` 追加当前世界的因果变化。可以新增图形、对象、程序和目的地，修改当前地表和对象，但不能以“重建整张地图”改写过去。既有程序定义和图形 ID 不得被静默覆盖，变形需新建定义并切换引用。地图变化后仍会验证玩家与结构出口。

## 生成调度

同一模型最多两路并发，当前位置两跳预取范围，缺失的直接出口优先，随后是反应和第二层。已访问区域保留；未访问草稿可根据新事件刷新但要保持已注册道路。每次真实请求都计入预算；最多一次 JSON/蓝图修复，不无声回退到离线模板。

地区响应通过世界 epoch、目标大纲版本、父地区与配置版本检查；普通玩家故事事件不会丢弃地区预取。当前世界反应仍要求故事版本与当前地区匹配，交互和战斗中的反应暂存到安全点。只有明确的 `reaction.future_updates` 才刷新对应未访问草案，旧草案保持可进入。调度、计时、日志及验收见 [PREFETCH_RELIABILITY.md](PREFETCH_RELIABILITY.md)。新规则经解释器执行，不为每个移动或每帧请求模型。

## 执行与保存

一次玩家操作、其事件链、目标奖励和地图变化在一个 SQLite 提交中完成。失败时恢复内存状态、地图缓存和待导演反应状态，不保留半次奖励。区域 runtime 保存变量、一次性执行记录、目标状态、计时器及有界位置历史。

存储沿用 state / regions / events，已访问地图按需加载，内存缓存上限六张。一个存档槽和启动器独占锁规则不变。无密钥进存档。新协议并不自动重建旧存档；新世界才能完整采用模型空间规划。

## 客户端

Godot 通过本机带令牌的 HTTP 获取权威状态。模型几何编译成纹理，可选动画帧按时间播放；自定义地表覆盖原来的固定纹理算法。碰撞与物体占地来自权威区域数据。操作和技能按钮来自可用动作列表，不再对在线生成固定为五个技能。

基础 UI、音乐、旧战斗兼容和底层渲染仍是固定代码。这一改造开放的是内容和行为表达能力，不承诺无限制玩法、专业级像素美术或自动证明谜题可解。
