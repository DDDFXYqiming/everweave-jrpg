# 运行时架构

当前在线入口先生成章节计划，再生成 Content Runtime v2 地区。章节协议见 [章节与游戏规格](CAMPAIGNS.md)，局部执行语法见 [内容协议](EXECUTABLE_CONTENT.md)，历史验证按 [文档目录](README.md) 中的阶段记录阅读。

模型传输默认使用 `chatgpt_provider.py`，通过 Everweave 自己的设备 OAuth 授权直接读取 ChatGPT Responses SSE，以 GPT-5.6 Luna / high 生成内容。`codex_provider.py` 仅保留为兼容与对照工具；API 服务仍由原 Chat Completions 适配器处理，但必须明确选择。登录、额度或传输失败不会跨服务回退。

## 生成任务与创作分工

- `kind=campaign` 由 `campaign_prompt.py` 描述、`campaign.py` 校验和安装。第一章同时安装 `game_spec.py` 定义的系统/资源规格；后续章节保持规格不变。
- `kind=direction` 由全局冒险导演根据真实事件复盘，追加任务、委托和受限连接。`adventure.py` 保存统一人物、技能、任务依赖、结局与制作记录；详见 [冒险导演](ADVENTURE_DIRECTOR.md)。
- `kind=region` 实现章节中的一个地点，输出 `scene/program/visuals/audio`。模型收到章节目标、旗标生产职责、地区用途和实际路线锚点，不再自行扩展父子目的地树。
- `kind=reaction` 处理当前位置的局部因果变化。可追加对象、绘图与规则或改变地表；在章节世界中，不能通过 `locations/future_updates` 改写章节图，应通过共享旗标影响已规划的连接。

`schema.py/content.py` 校验地区和规则，`normalization.py` 只纠正有唯一解释的格式差异。`scene.py` 按蓝图施工并布置纯视觉点缀；`runtime.py` 执行有界表达式和效果；`gameplay.py` 把解释器接到实际动作与事务。原始失败响应及具体诊断交回模型修复，不调用下载的脚本。

## 章节状态与连接图

`state.campaign.chapters` 保存每章的目标、地点、连接及方向、旗标与接续说明。`state.topology` 继续保存地区的准备/到访状态和元信息；其中 parent/children 不能作为章节世界的完整邻接关系，实际路线来自章节 links。

地区读取 `chapter.FLAG`，通过 `op:chapter` 修改本章共享旗标；不同章节的同名旗标隔离。里程碑完成、隐藏连接揭示和通行条件会随提交后的状态更新。地区响应必须提供计划路线锚点；下一章通过 `chapter_gate` 接入，跨区时使用同一连接的对应门口。

`read_views.py` 生成玩家旅图，只披露到访地区及其已揭示的连接。纯预生成不等于发现。锁闭路线保留说明，客户端标记路线时排除锁闭连接；不提供点击地图直接传送。

## 调度与持久化

导演最多两路并发。需要规划时先执行章节任务，再生成地区；附近地区沿图做两跳预取，同距离优先当前活动章节。已知但未揭示的路线也可预生成，其内容不会因此出现在旅图中。不是把整张无限图一次性生成。

章节任务通过 epoch 和 campaign revision 判断是否仍有效，地区检查目标草案/父信息及相关人物、技能、委托依赖。局部反应继续检查当前地区及故事版本。全局复盘按事件批次确认，并在当前权威状态上重新验证提案，不要求玩家在模型思考期间停止交互。等待出口与附近地区先获得生成资源；普通走路不请求导演。战斗或交互中的局部反应可延后应用。每次真实模型请求计入预算，生成和一次修复仍失败后等待重试。

一次玩家操作、事件链、共享状态、奖励和地图变化在 SQLite 事务内提交；失败回滚。章节计划、游戏规格与玩家资源随世界保存，已加载地区使用有界内存缓存。新章节不是清空或替换旧章。当前不提供旧世界向章节世界的转换流程，请新建存档验证。

## 系统和客户端

游戏规格启用战斗、物品、装备和成长，声明 0～8 种资源。停用系统同时影响校验、操作和界面；`op:resource` 在范围内修改自定义资源。战斗仍使用有限的 hp 机制，失败模式可退回入口或结束本局，非战斗世界可不设置自动失败。

Godot 通过本机带令牌的 HTTP 获取权威状态，按规格显示称谓、资源和目标，按可用动作生成按钮。`visual_compiler.gd` 编译库图、组合和原创绘图；地表变化、邻接边缘和点缀在本地完成。音频由地区定义驱动。设置、语言、存档、输入和渲染本身仍由固定客户端代码实现。

素材检索以题材适配优先，受系统开关约束的模块也会过滤。现代/科幻没有相容图像时需要原创，不保证覆盖所有题材或理解所有混合风格。图结构检查不等于证明整章逻辑可解，人工试玩范围见 [交付记录](CAMPAIGN_VALIDATION.md)。
