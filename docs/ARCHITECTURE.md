# 运行时架构

当前在线入口先生成章节计划，再生成 Content Runtime v2 地区。章节协议见 [章节与游戏规格](CAMPAIGNS.md)，局部执行语法见 [内容协议](EXECUTABLE_CONTENT.md)，历史验证按 [文档目录](README.md) 中的阶段记录阅读。

模型传输按世界连接设置选择。`chatgpt_provider.py` 通过设备 OAuth 读取订阅 Responses SSE；`director.py` 的共享 Chat Completions 传输负责兼容端点、流式解析、用量与有限补试。复杂地区的玩法和视听作者复用同一传输与思考等级。`codex_provider.py` 保留订阅兼容入口。

## 生成任务与创作分工

- `kind=campaign` 由 `campaign_prompt.py` 描述、`campaign.py` 校验和安装。第一章同时安装 `game_spec.py` 定义的系统/资源规格；后续章节保持规格不变。
- `kind=direction` 由全局冒险导演根据真实事件复盘，追加任务、委托和受限连接。`adventure.py` 保存统一人物、技能、任务依赖、结局与制作记录；详见 [冒险导演](ADVENTURE_DIRECTOR.md)。
- `kind=region` 实现章节中的一个地点。复杂新地区由本机从导演委托建立共享约定，再让玩法分支输出 `scene/program`、视听分支输出 `visuals/audio`，两条同模型请求按可用容量执行，最后合成为普通地区对象。模型收到章节目标、旗标生产职责、地区用途和实际路线锚点，不再自行扩展父子目的地树。简单、刷新和修复任务仍可一次生成，细节见 [地区双路制作](REGION_PIPELINE.md)。
- `kind=reaction` 处理当前位置的局部因果变化。可追加对象、绘图与规则或改变地表；在章节世界中，不能通过 `locations/future_updates` 改写章节图，应通过共享旗标影响已规划的连接。

`schema.py/content.py` 校验地区和规则，`normalization.py` 只纠正有唯一解释的格式差异。`scene.py` 按蓝图施工并布置纯视觉点缀；`runtime.py` 执行有界表达式和效果；`gameplay.py` 把解释器接到实际动作与事务。原始失败响应及具体诊断交回模型修复，不调用下载的脚本。

## 章节状态与连接图

`state.campaign.chapters` 保存每章的目标、地点、连接及方向、旗标与接续说明。`state.topology` 继续保存地区的准备/到访状态和元信息；其中 parent/children 不能作为章节世界的完整邻接关系，实际路线来自章节 links。

地区读取 `chapter.FLAG`，通过 `op:chapter` 修改本章共享旗标；不同章节的同名旗标隔离。里程碑完成、隐藏连接揭示和通行条件会随提交后的状态更新。地区响应必须提供计划路线锚点；下一章通过 `chapter_gate` 接入，跨区时使用同一连接的对应门口。

`read_views.py` 生成玩家旅图，只披露到访地区及其已揭示的连接。纯预生成不等于发现。锁闭路线保留说明，客户端标记路线时排除锁闭连接；不提供点击地图直接传送。

## 调度与持久化

导演最多运行两项逻辑任务，实际模型请求共享两个容量槽。等待中的出口、当前位置的反应、章节与导演复盘优先于普通邻区预取。已有可玩地区时，一个双路制作任务同时最多占一个槽，给玩家当前需求保留调度空间；首区可以并行制作玩法和视听。已完成组件写入 SQLite，失败分支可续作。附近地区沿图做两跳预取，旅图仍按已揭示路线展示。

章节任务通过 epoch 和 campaign revision 判断是否仍有效，地区检查目标草案/父信息及相关人物、技能、委托依赖。局部反应继续检查当前地区及故事版本。全局复盘按事件批次确认，并在当前权威状态上重新验证提案，不要求玩家在模型思考期间停止交互。等待出口与当前位置的需求先获得生成资源；普通走路只执行本地规则。战斗或交互中的局部反应可延后应用。每次真实模型请求计入预算，生成尝试数由连接设置约束。

一次玩家操作、事件链、共享状态、奖励和地图变化在 SQLite 事务内提交；失败回滚。事务保存全局状态的 before-image，地区在首次触达时建立回滚副本，已有缓存顺序一并恢复。条件展示使用共享的只读求值视图。章节计划、游戏规格与玩家资源随世界保存，已加载地区使用有界内存缓存，章节通过接续门持续扩展。

`causal_memory.py` 从权威任务、委托、人物和章节旗标派生有界上下文：当前目标与依赖、较早仍活动的目标、待制作委托优先，近期事件作为补充。遗漏数量随切片传递，人物状态和任务完成度以存档为准。

观测型 Jev 内容审查在内容提交后进入单工作线程的有界队列，结果绑定世界 epoch、目标版本与任务标识。队列、取消、过期和请求用量独立记账；素材选择仍服从制作任务的剩余时限。

## 系统和客户端

游戏规格启用战斗、物品、装备和成长，声明 0～8 种资源。停用系统同时影响校验、操作和界面；`op:resource` 在范围内修改自定义资源。战斗仍使用有限的 hp 机制，失败模式可退回入口或结束本局，非战斗世界可不设置自动失败。

Godot 通过本机带令牌的 HTTP 获取权威状态，按规格显示称谓、资源和目标，按可用动作生成按钮。地区静态定义以 `region_static_token` 复用，完整响应通过 `region_static_fields` 声明缓存字段；后续响应完整传递动态字段。客户端先判定实例、世界和快照序号，再合并对应静态定义。服务端在世界锁内准备独立响应，在锁外编码和写入网络。`visual_compiler.gd` 编译库图、组合和原创绘图；地表变化、邻接边缘和点缀在本地完成。音频由地区定义驱动。Web 画布随浏览器视口铺满，场景相机按可见格数缩放并跟随角色，HUD 保持独立尺寸；实体点击通过相机的逆变换定位。设置、语言、存档、输入和渲染由客户端代码实现。

素材检索以题材适配优先，受系统开关约束的模块也会过滤。现代/科幻没有相容图像时需要原创，不保证覆盖所有题材或理解所有混合风格。图结构检查不等于证明整章逻辑可解，人工试玩范围见 [交付记录](CAMPAIGN_VALIDATION.md)。
