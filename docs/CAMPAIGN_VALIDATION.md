## 真实模型记录

此前使用 DeepSeek Flash、思考等级 low，在独立测试目录尝试现代医院生存题材。

| 记录 | 实际调用 | 用量与结果 |
|---|---:|---|
| `hospital` | 2 次，含 1 次修复 | 输入 4,386、输出 24,413 tokens，约 108.22 秒；当时连接 ID 长度限制导致计划未应用 |
| `hospital-play` | 4 次，含 2 次修复 | 输入 49,002、输出 71,683 tokens，约 268.72 秒；复用已有计划，按当时校验器只成功应用大厅，走廊仍失败 |
| `hospital-final` | 0 次新增请求 | 修正连接 ID 与音频约束后，重放首份计划、大厅和走廊原始响应，成功保存 6 个计划地区中的 2 个 |

总计 6 次真实请求、输入加输出 149,484 tokens。这些包含调试与失败成本，不是稳定性能基准。音符、长音和合成环境声的限制修正后，原始内容可本地回放；没有把回放描述成新的“一次在线生成成功”。

首份计划有 6 个地区、7 条连接，含电力/门禁依赖与隐藏通道。大厅有 20 张原创图形配方，复用了 5 项音效资产；界面称谓为“值班急救员、急救包、急救记录”，资源为生命、弹药、感染与电量，未启用魔力、金币和成长。已落地的相邻走廊有三个出口，其中隔离病区需要条件解锁。

原始响应、历史失败结果、快照与测试存档保留在本机 `userdata/campaign-validation/`，不提交到 Git。这些结果证明规划和地区内容能通过当前接口落地，不证明所有六个地区均已生成或能完成整章。

## 未完成的实机验收

Computer Use 在进入医院试玩时收到用户按 Esc 停止的信号，因此本轮未完成实机跨地区试玩。静态客户端渲染和自动测试不能替代它。2026-09-14 用户明确自行试玩，本次交付保持这个边界。

待玩家验证的重点：章节目标是否易懂；跨区线索是否能实际取得并解锁门禁；隐藏路线是否可发现；走廊后续是否继续出现合理分支；下一章接续与回访是否稳定；资源消耗、战斗和故事节奏是否合适。问题反馈可以附世界设定、操作步骤和相关错误信息。

## 如何开始验证

使用新的独立存档，在在线模式下创建世界以获得游戏规格与章节计划。已有旧世界没有迁移验收，本轮不以兼容它们为目标。若本机仍保留医院样本，可以运行：

```powershell
python launch.py --data-dir ./userdata/campaign-validation/hospital-final
```

启动后恢复生成需要在界面应用配置或点击“继续生成”；后续请求计入新进程的调用预算。该目录是本机调试产物，不包含在下载的源码里，其他机器请新建世界。
