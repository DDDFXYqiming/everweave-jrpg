# 冒险导演交付与验证 · 2026-09-15

本轮从 `4f86538` 继续实现全局创作与内容工作器分工。保留混合素材、旁侧任务的资产缓存与索引改造，所有改动在 main；不迁移旧存档。

## 已实现

章节规划可定义持续人物、任务依赖、能力简报、委托、收益上限和结局。真实事件积累后，独立 `direction` 任务提出受限追加；地区和委托作者输出具体场景、规则与图形。关系、技能、任务、道路与玩家进度仍由同一份 SQLite 状态管理。协议与限制见 [冒险导演](ADVENTURE_DIRECTOR.md)。

同时修复地区作者缺少完整门禁/发现条件的问题，以及别的敌人的钩子阻止当前敌人默认攻击的问题。场景支持人物肖像与有后果的选择，原生输入验证发现并修复了人物名字被挤成竖排的布局问题。

## 真实模型生成

使用独立雾港测试世界，设定为年轻联络员与机械师米拉寻找失踪领航员，恢复潮汐灯、让救援船出航。要求人物关系、回环、支线、有代价的战斗与跨地区能力。

| 阶段 | 真实请求 | 结果 |
|---|---:|---|
| 章节 + 开局码头 | 3 | 章节首次多出一个不支持的地区字段，修复后通过；码头通过。共约 199 秒 |
| 根据实际选择和探索进行全局复盘 | 1 | 首次通过，约 25.6 秒；新增萨布尔账本支线、条件生产委托、后续结果及未访问海窟用途 |
| 黄铜工坊首次生成与修复 | 2 | 失败。第一次有未知表达式，修复后暴露 `learn` 引用尚未实现的技能 |
| 修正技能协议和诊断后的定向修复 | 1 | 保留原场景，约 27.3 秒通过；提供了全局技能 `brass_repair` 的可执行实现 |

总计 **7 次真实调用**，输入 **77860**、输出 **99092 tokens**；输出包含服务返回的思考 tokens。不是全都首次成功，也未做优化前后同条件成本对比，因此不声称这版已降低整体生成费用。

工坊失败样本推动了实际修复：要求委托中的新技能必须有同层 `abilities` 定义，明确学习效果不等于定义技能；缺失技能与其他独立语法问题同时报告，包含字段路径与技能简报。没有通过删除学习效果或自动塞入固定技能来绕过失败。

本地原始证据位于 `userdata/adventure-validation/{harbor,review,worker,worker-repaired}/` 的 trace、结果和独立数据库。它们含完整模型内容，不加入 Git。当前只完成 **5 个计划地区中的 2 个**；导演追加的海窟账本尚未制作和实际游玩。

## 自主试玩

先以 Computer Use 验证开场选择、移动和指引牌，开场选择实际使米拉信任从 0 变成 6。收到“测试太慢”的反馈后，改用 [快速试玩](FAST_PLAYTEST.md) 的玩家可见投影和正常 HTTP 动作。探索目标由测试者逐次根据观察选择，工具没有固定通关策略。

实际完成了以下连续体验：

1. 检查码头潮汐灯，得到人为熄灯线索；向船长询问其他走法，得到海窟提示。
2. 正常走到出口进入黄铜工坊；读取航海日志，得知第三道潮痕的校准提示。
3. 消耗黄铜零件装齿轮，按游戏提示转动校准环，读取潮汐结果，推进“黄铜海图”主线。
4. 向米拉讨教学会“黄铜维修”；能力按钮由真实学习效果出现。
5. 与失控吊臂战斗：普通敲击造成伤害并遭反击；泼灯油消耗 1 灯油，敌人蓄力；随后击败敌人并获得规则定义的零件与铜币奖励。
6. 沿正常出口返回码头，使用工坊学到的能力。零件 2→1、体力 22→24，证实能力跨区保存且效果生效。

记录包含 36 次意图/观察命令、10 次目标寻路，累计 **152 个正常移动动作**。寻路加移动/交互的总执行时间约 **7.45 秒**：8 步为 0.44 秒，17 步为 0.76 秒，36 步跨区为 1.58 秒。该数字不包括判断、工具往返、编写工具或模型生成时间，不能当作完整试玩时长。

快速工具首次战斗调用发现缺少原客户端的 `rule:` 前缀；该调用被拒绝，没有改变战斗。已修复并补真实 HTTP 战斗回合回归。公开观察记录为 `userdata/adventure-validation/fast-play.jsonl`，后端操作日志保留拒绝与成功记录。

## 自动与原生验证

- Python 全量 **270 项测试通过**，覆盖导演约束、原子回滚、共享人物、场景选择、跨区技能、单向连接、新条件生产委托和快速操作。
- `tools/test_native.py --adventure` 在 Windows OpenGL 实际渲染器及 headless 运行通过。实际 Godot 输入点击选择、学习能力、移动过出口、在下一地区使用能力并扣除资源。
- `--content --headless` 和 `--hybrid --headless` 通过，保留原有动态动作、机关、战斗、旅图、音频和混合素材链路。
- CI 加入冒险原生测试；所有固定回归均为零模型调用。

原生截图在 `userdata/adventure-e2e/`，真实模型场景的只读 Godot 重渲染在 `userdata/adventure-validation/current-gallery/`。截图用于视觉检查，实际交互证据另由动作日志和原生测试给出。

## 尚未达到的效果

完整章节通关、所有结局、长期导演节奏、多世界成功率和长期经济平衡尚未验收。可携带能力仍是有限效果组合，本轮“黄铜维修”实现为零件换恢复，不能据此宣称已支持任意跨区物体技能。

实际工坊仍有部分禁用操作只显示泛泛提示；同一进展被章节里程碑、主线任务和局部目标重复记入日志。主界面做了同名目标去重，但尚未统一这些目标的语义身份。不同地点的人物表现仍可能与已有叙事不完全一致；身份和关系持久化不能单独保证对白连贯。场景和战斗比旧实现有了更多可执行内容，内容质量仍需要继续用真实游玩反馈改进。
