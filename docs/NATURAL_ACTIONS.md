# 自然语言行动

## 玩家入口

游戏底栏的气泡图标与 `T` 打开一行行动输入。输入意图后按 Enter 或发送图标，由当前已连接模型理解，先显示本地候选动作。核对后再次按 Enter 或勾号确认，交给本地运行时执行；修改输入后重新发送会解释新的意图。输入期间角色保持原位；关闭输入框后恢复普通快捷键。结果以一行短消息呈现。

## 请求与进度

`POST /intent` 接收 `text` 与当前世界的 `epoch`，要求独立、唯一且至多 96 字符的 `X-Request-ID`。文本至多 240 字符。服务立即返回正常快照，异步进度位于 `snapshot.intent`：`id`、`status`、`text`、`message`。状态为 `idle`、`resolving`、`proposed`、`completed`、`rejected`、`stale` 或 `error`。`proposed` 是待确认动作，`POST /intent/confirm` 使用 `id`、`epoch` 和独立请求标识确认；确认复用已解释结果。

每个服务同时处理一条行动意图。模型请求复用连接配置、思考等级、请求容量和用量预算；玩家发送是明确的调用触发点。后台内容制作的暂停状态保持独立。

## 解释与执行

服务端从权威状态列出有限候选，模型只选择候选标识。本地映射负责把标识转为既有动作：四方向一至四格移动、等待、邻近对象交互、当前已提供的选项、已有物品及规则能力。候选生成与执行分别检查物品、费用、距离、条件和当前交互状态。更远的人物需要先通过正常移动接近。

动作仍通过 `world.action` 提交。多格移动逐步执行真实事务；遇到障碍、战斗、交互画面或换区便停止，结果记录实际发生的步数。玩家在模型思考期间接管操作，或世界、地区、交互上下文改变时，旧意图过期。

服务记录 `intent.started`、解析结果、应用或拒绝原因，以及实际动作、步数、模型和用量。重启留下的未完成意图转为过期状态，玩家可重新表达。
